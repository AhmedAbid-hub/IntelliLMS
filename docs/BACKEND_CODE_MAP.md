## Architecture and app modules

[config/urls.py](../backend/config/urls.py) registers every project API. `DefaultRouter` registers viewsets and action routes; `STRUCTURES` in academics.views generates eight structure viewsets (batches, curriculum, units, years, terms, programs, sections, courses). Other endpoints use function/API views. There are four domain apps and no app-specific URL files.

## Serializers and service boundaries

- `TenantSerializer` and `serializer_for(model, base)` in [academics/serializers.py](../backend/apps/academics/serializers.py) generate serializers such as OfferingSerializer. These names may appear in OpenAPI without a handwritten class of that name.
- `LearningSerializer` extends tenant validation and role-specific visibility. `attempt_data` in learning.views customizes attempt output; do not expose stored answers/marks merely because the model contains them.
- InstituteSerializer and MembershipSerializer are in accounts.views; platform/appointment/profile/workflow input serializers live beside their specialized handlers. The three app `contracts.py` modules and insights.report_contracts describe action/report payloads.
- Admission, progression, lifecycle, corrections and bulk enrollment use transactions/locks around validation and mutation. Readiness/setup/report endpoints are reads; they should not become hidden mutation paths.
- Response contracts in [docs/openapi.yaml](openapi.yaml) are generated evidence. The source endpoint and serializer remain authoritative if a snapshot drifts.

## Endpoint conventions and permissions

The catalog below covers **148 distinct paths**: **144 versioned paths** (including the API discovery root), and health/readiness/schema/docs. Django admin's generated internal URLs are excluded; its entry is `/admin/` in config.urls. `{id}` normalizes DRF's pk regex and Django's UUID converter. HEAD/OPTIONS and duplicate format-suffix routes are not separately counted.

Methods listed are registered handlers allowed by `http_method_names`; **they are not blanket authorization**. Some intentionally reject direct CRUD:
- `enrollments` create/update/delete are denied; use offering bulk-enrollment.
- `submissions` POST collection raises validation error; submit via assignment action.
- `attempts` POST collection raises validation error; start via quiz action.
- `notifications` POST collection is denied; internal events create notifications.
- Institute deletion is refused; deactivate instead. Offering deletion is refused; archive instead.
- Published/history-linked records can reject DELETE even when a route exists.

Policy shorthand (exact functions/tests in [roles map](ROLES_AND_PERMISSIONS_MAP.md)):
**P** Super Admin platform/admin-account scope; **I** active institute + Admin management; **O** Scope.offerings (Admin institute, Head unit, Teacher assignments, Student enrollment); **T** assigned-instructor writes; **S** self/student records; **C** governance snapshot/delegation/independent-review checks; **N** own institute notifications; **A** auth/profile; **R** scoped report pairs; **M** staff scoped model/history reads, assigned effective-Teacher generation. School restrictions apply in Scope, TenantViewSet and institution helpers.

“Contract” lists request/response schema names from the current OpenAPI snapshot, not necessarily a standalone Python class. Paginated wrappers are generated; binary responses have no named JSON schema. For CRUD, collection GET/POST means list/create and detail GET/PUT/PATCH/DELETE means retrieve/update/partial_update/destroy. The source view links and model map identify supporting services, validation and tables.

## Background processing and external effects

No Celery task module, broker or worker service is configured. [notify_deadlines](../backend/apps/learning/management/commands/notify_deadlines.py) is an explicit management command intended for an operator-controlled scheduler. [notify_event](../backend/apps/learning/notifications.py) creates in-app events; invitation/reset email uses configured Django mail transport, with invitation sending scheduled through transaction.on_commit where applicable. There are no project-defined signal receiver modules in the inspected domain apps.

Class analysis stores runs/items but progresses through explicit HTTP advancement. [train.py](../backend/ml/train.py) is an offline CLI, not a request handler. None of these facts implies automatic periodic jobs are deployed.

## Safe editing and tests

Change view-level business rules in the specialized service first, while retaining Scope checks, tenant-filtered lookup and serializer validation. For new fields, examine related-label serialization, dynamic resource form config and OpenAPI contracts. For grade changes, inspect gradebook, release visibility, governance snapshots and academic_results together. For academic structure changes, inspect institution rules, eligibility, admission and progression together.
