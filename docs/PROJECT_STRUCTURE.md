# Project structure

This inventory reflects the reorganized checkout. Existing feature-based folders remain; no parallel second application or replacement model layer was introduced.

| Area | Responsibility |
|---|---|
| `frontend/src/app` | Composition, providers, route tree and named resource registry |
| `frontend/src/pages` | Named entry points for existing resource URLs |
| `frontend/src/components/layouts` | Shell state, sidebar, header, breadcrumbs, navigation and workspace guard |
| `frontend/src/features` | Actual feature workflows and presentation; focused resource forms, corrections and dashboard bodies |
| `frontend/src/lib` | API client, institution policy projection, terminology, URL filters and frontend access guard |
| `backend/apps/accounts` | Login/session identity, memberships, invitation transport and staff lifecycle |
| `backend/apps/academics` | Structures, placement, progression, offerings and enrollment |
| `backend/apps/learning` | Lessons, files, assignments, quizzes, attendance and audited corrections |
| `backend/apps/insights` | Scoped dashboards/reports, grades, audit and experimental predictions |
| `backend/config` | Settings, environment guards, URL registration and health |
| `backend/ml` | Existing public-data training/inference and artifact contract |
| `scripts` | Local start, guarded tests, operational verification and generated documentation |
| `deployment` | Existing production Docker/Nginx files |

Models and migration files were intentionally not split or renamed: their current domain grouping is coherent, and schema stability matters more than adding folders. Existing focused service files also retain their names. `views/__init__.py` is a compatibility export, not where new feature logic should be placed. Shared academic structure viewsets are configured centrally in `config/urls.py`; find their fields in the existing serializers/models.
