Real-domain certificate issuance/renewal, actual SMTP, off-host/media recovery and operational deployment remain unverified. No service has been deployed publicly.

Trends aggregate daily scores in SQL and process gradebooks in batches, and department distinct learner/course counts now run in SQL. No virtualized table implementation. Score trends use current released marks grouped by submission date, not historical snapshots.

No lawful historical cohort or external validation was provided. Per-institute registrations, approval state and feature snapshot exports remain enhancements; do not present demo estimates as validated academic decisions.
4. **Large rosters/quizzes:** attendance now retrieves 50 students and their saved statuses per page, with search and atomic per-page saves. The API still accepts up to 500 requested records per transaction. Unsaved edits block page/search changes, and failed saves retain edits. Whole-roster atomic submission is not offered. Quiz questions and attempt review still traverse the full assessment; unusually large quizzes need further capacity/usability evaluation.
5. **Assessment scope:** configurable letter bands/points, pass thresholds, repeat-attempt rules and missing-category rules are now integrated. Results remain provisional; finalized transcripts, credit-weighted GPA and retroactive historical grade snapshots are not implemented. Grade history is staff-only; old seed records do not have fabricated audit events.
6. **Administration:** persistent platform overview, institute details, administrator listing and entry to existing people management are implemented. Academic terminology now renders across settings/forms/tables/navigation. Public platform name/support/login notice configuration is implemented, validated and audited. Infrastructure secrets remain environment-managed. Role-denial routing and a read-only global platform audit page are implemented; exhaustive CRUD/role browser permutations remain incomplete.
7. **Scheduling:** conflicts respect overlapping terms, and changing instructors revalidates existing slots. Term date changes now revalidate room/instructor conflicts and API calendar/schedule writes lock the institute before validation. No holidays, exceptions or student overlap checks. The concurrent room-booking test passed on PostgreSQL. More adversarial scheduling permutations remain possible.
8. **File lifecycle:** DOCX ZIP structure, expanded size and unsafe entries are validated. No antivirus, retention jobs, orphan cleanup, encryption-at-rest management or object-storage adapter. Structural validation is not malware detection.
9. **Operational security:** Nginx configuration now shares an IP-based auth rate limit across workers; TLS/proxy syntax and HTTP 429 behavior passed in the production container smoke. Direct backend deployments still have only process-local throttling. Audit covers academic mutations, not every sensitive read or full before/after data; institute configuration changes now have atomic changed-field audit events. Direct ORM/SQL writes bypass API validation; no PostgreSQL RLS.
10. **API documentation:** CRUD OpenAPI plus action contracts in api.md; assessment action request/response schemas now use explicit serializers and contract tests. Authentication/invitation/import, aggregate, prediction/model and remaining action contracts now have explicit serializers. Response-contract regression checks passed for all five role dashboards, reports and unavailable-model behavior; arbitrary grading-rule/audit detail JSON remains intentionally extensible. Computed relation labels are now explicit read-only nullable fields; quiz staff metadata and attempt list/detail contracts are documented and regression-tested. Extensible JSON remains intentionally open-ended. Program/section uniqueness migration does not silently merge historical duplicates; resolve any existing duplicates before deploying it.
11. **Interface:** generic resource pages and inline feedback work; breadcrumbs and dismissible save notifications are now integrated; formal accessibility auditing and exhaustive workflow coverage remain incomplete. Dark mode/localization are optional enhancements.
12. **Testing:** Chromium, SQLite and PostgreSQL 17 have now been verified locally. The new Python E2E launcher supports Windows/POSIX paths, but Linux CI execution remains unverified locally. Firefox/WebKit, real SMTP and broader concurrent and CRUD/role permutations remain open. The four current PostgreSQL race cases passed. Deterministic stale-validation tests pass on SQLite. See testing.md for exact current results.

Continue in this repository. Preserve working code and tests; prioritize remaining required integrations and production verification without expanding optional features into invented requirements.
